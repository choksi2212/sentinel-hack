date, this file wins and that document is the bug to fix.

## What this does NOT do

It does not replace the per-day plans in the execution manuals. Those tables
allocated six build days across 1–6 September; that allocation is spent and the
work it describes is largely done. **No new day-by-day plan is invented here** —
re-planning the recovered time is a team decision, not a documentation edit, and
a table written unilaterally would become the next stale document labelled
authoritative.

What changed with the extension is *scope*, not just slack: items deferred as
"not reachable before the 7th" are reachable now and should be re-triaged rather
than left deferred by inertia.

## Why this file exists at all

The dates were duplicated verbatim into six documents. When they moved, all six
became wrong simultaneously and none of them knew it — the failure was the
duplication, not the extension. Dates now live in exactly one place and the
other documents point here. Do not copy the table above into another file.
